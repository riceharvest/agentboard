# Changelog

## Unreleased

- Command cards: `ab add "title" --cmd "shell command" [--cwd DIR] [--result TEXT] [--dep ...] [-l ...]` (MCP `ab_add` with `cmd`) makes a card whose work is a command, not a model run (after Vercel Board's `tasks run -- <cmd>`). The runner claims it like any card (slots, RAM gate, deps, `--after`, priorities, board slot caps) but starts the command itself via `sh -c`: no harness, no model, no bucket, so quota gating, caps and the launch pacer never apply and the run leaves no `usage` rows and no launch-budget count. It renews the lease while the command runs, exports `AB_TASK` / `AB_ACTOR` (`cmd#<run>`) / `AB_BOARD` / `AB_HOME`, posts the last 40 lines of output (stdout+stderr) to the thread and settles by exit code: 0 = done (result = `--result` or the last output line), 75 = released without using an attempt (retried after the `backoff`), anything else = failed attempt with the output tail. Timeout, `ab kill`, cancel, runner stop and the idle rule (no output for `stall_idle_after`; label `stall=off` for quiet commands) behave as for agent runs, except that a stalled command counts as a failed attempt. `ab ls` / `ab show` / `ab snapshot` (task `kind`, `runner.children[].kind`/`cmd`) show kind `cmd`; `ab runner status` lists running command cards. Schema: new `tasks.cmd` column (auto-migrated). Runner change: `ab runner reload` needed.

- Per-tier extra CLI flags: new `extra_args_tier` config (`tier -> {harness -> [args]}`), appended after the existing per-harness `extra_args`, keyed by the tier the candidate entry sits in. Empty by default (launch command unchanged). Runner change: `ab runner reload` needed.

- Global `gating` option: `ab config set gating quota` makes every launch depend only on quota, i.e. the `max_5h_pct` / `max_7d_pct` and soft caps plus provider limits (cooldowns from real limit errors). Pace lines (`pace_lead_h`, `pace_7d_lead_h`) and the per-interval launch budgets (pace / AIMD) are ignored while it is on; the cap values stay stored, so `gating pace` (default) restores the old behaviour. `ab usage` shows budget `quota`. Runner change: `ab runner reload` needed.

- `ab` infers the task, actor and board from a live run's home when `AB_*` are not exported: a shell whose `HERMES_HOME` or cwd is `<root>/profiles/ab-run-N` (with the `ab-run.json` marker the runner writes there) resolves to run N's card and owner, and only if the run is live (process alive, card claimed by it, same board as any `--board`/`AB_BOARD`). `ab done/note/fail` accept an empty or missing task id and a summary that lands in the id slot. Anything else (ambiguous homes, stale or ended runs, a missing marker, another board) refuses with a reason and writes nothing. The runner brief now prints literal task ids in its commands and the `AB_TASK/AB_ACTOR/AB_BOARD` prefix to use when a shell lacks them. Runner change: `ab runner reload` needed.

- Stall watchdog: the runner reads each live run's own logs through an optional per-adapter `probe()` (Hermes per-run `agent.log`, Claude session transcript; Codex via its JSON stream) and (1) kills a run stuck in provider 429 retries longer than `stall_retry_after` (default 10m) as a `limit` on its bucket (cooldown `stall_cooldown` 30m or the provider's reset hint, AIMD halving, reroute, no attempt counted), (2) kills a run with no sign of life longer than `stall_idle_after` (default 45m), retries once, then holds the card for the overseer (`stalled=overseer`, `ab anomalies`). `ab runner status`, `ab snapshot` (`runner.children[].stall`) and the TUI show `retrying 429 (12m)` / `idle 40m`. Per-card label `stall=off|90m`; thresholds accept `off`.

- Hermes runs with `hermes_isolate=false` (shared gateway): `ab kill`, timeout and lease expiry now stop the gateway-side session, not only the `hermes chat` client. The client's SIGINT only detaches ("accepted work continues at the gateway"), so the runner reads the session id (stderr `Session:` line, or the gateway session row for the run's workdir) and sends the documented `session.interrupt` over `hermes gateway attach --json` + WebSocket JSON-RPC (zero extra dependencies), once per run, and logs the outcome in the runner log. The shared gateway process is never stopped. Isolated runs (default) already stop their per-run gateway.

- `ab park`: park a claimed card on a long external job and exit — `--pid PID` (wake when the process exits, start-time guarded) or `--file PATH [--grace 60s]` (wake when the file exists and stops growing), with a required `--note`. The run ends with outcome `parked` (no attempt counted), the slot frees immediately, the runner checks wake conditions every tick, and a fresh agent resumes the card with the park note and the parked run's last output lines in its brief. Parks survive a runner reload; `ab ls` / `ab show` / `ab snapshot` (task `park` field) and the TUI show what a parked card waits on. GUIDE: anything expected to take > 20 min runs detached and the card parks.

- Hermes runs: the isolated per-run session transcript is exported to `runs/<run>.hermes-session.jsonl` before the temporary `HERMES_HOME` is deleted (audit what an agent did around a kill/timeout); with `hermes_isolate=false` the brief now spells out the `AB_*` values because a shared gateway's tools don't inherit them.
- Runner auto-worktree: when a ready card's workdir is a busy git checkout, the runner automatically starts it in a per-task git worktree (`ab/<task>` from `HEAD`) unless disabled per card (`-l worktree=off`) or globally (`ab config set auto_worktree false`). `ab ls --ready` reports `workdir busy (auto worktree off)` only when a card actually waits.
- Worker env hygiene: the runner exports `AB_RUN_HOME`, and `ab` strips `AB_RUN`, `AB_ACTOR`, `AB_BOARD`, and `AB_TASK` whenever invoked with a different `AB_HOME` than the worker's own board.
- `ab-tui`: show per-bucket pacer launch budgets (`launch_budget` / `budget_why`) in Usage, surface and toggle `pacer` (`P`) and `auto_worktree` (`w`) in Ops (and `:pacer` / `:auto_worktree` in the palette), render intended negative outcomes (`labels.outcome=negative`) with a neutral `NEG` badge excluded from dead-card failure counts and red glitch effects, and display worktree metadata (`worktree_branch`, `worktree_dir`, `worktree=off`) and ready `wait_reason` in Card detail.
